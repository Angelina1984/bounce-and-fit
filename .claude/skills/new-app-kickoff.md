## Trigger

The user has a new app or game idea (or is pivoting to one) and either asks for help scoping it, asks "what should I start with," or is already producing design docs / code / art for it. Also trigger proactively if the user jumps straight to visuals, branding, or a formal architecture document before the concept and MVP scope are settled.

## Steps

1. **Concept, one paragraph.** Who it's for, the core hook or core loop (for a game: the one action a player repeats that's fun on its own, before art/story), and why now. If it can't be stated in a few sentences, sharpen it before continuing.
2. **Fast competitive scan.** Web search for existing products in the same niche/genre — who's already there, at what scale, what's missing. Cheap to do now, expensive to skip (a saturated genre or an existing direct competitor changes the whole plan).
3. **MVP scope.** The smallest version that tests the core hook/loop. Write explicit in-scope and out-of-scope lists — don't let scope grow before anything is validated.
4. **Platform / tech direction.** A decision (engine, stack, target platforms), not a formal document yet — driven by what the MVP scope actually needs.
5. **Ugly prototype.** Build the smallest playable/testable slice — gray boxes, placeholder art — that proves the loop or flow actually works. This is the step people skip by jumping to polish; it's the one that tells you if the idea works.
6. **Look-and-feel, only now.** Logo, color palette, art style, UI polish, buttons, icons — deliberately last, because it's the most expensive layer to redo and you don't know what it should look like until the concept is proven.
7. **Formal architecture document, last.** Written once MVP scope and platform are settled — it documents decisions already made, not a place to make them.

## Verification

Before treating the idea as build-ready, confirm: the concept is stated in one paragraph; a competitive scan has actually been done (not assumed); the MVP scope has explicit in/out lists; the target audience is one coherent group, not two incompatible ones bundled together (a smell: an audience spanning very different needs, e.g. "kids and elderly" on one control scheme, usually means the concept needs sharpening rather than genuinely broad appeal); and an ugly prototype exists that tests the actual hook, not just the menu/UI.
